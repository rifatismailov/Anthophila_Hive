# docscan-critical — правила пошуку критичної інформації DocScan

Приватний репозиторій. Правила з теки `critical/` потрапляють у **той самий** пакет правил `DocScan-rules.zip`, що й
основні правила, у теку `critical/`. На ПК вони лежать у `C:\Program Files\DocScan\rules\critical\` і працюють на
всіх ПК з DocScan (третій прохід: документ з критичною інформацією → черга E5Search).

```
critical/          правила: скільки завгодно файлів *.yar, лише верхній рівень, імена латиницею (zsu.yar, bank.yar)
tests/match/       документи, які МАЮТЬ спрацювати (будь-яка вкладеність)
tests/no-match/    документи, які НЕ мають спрацювати
```

## Як додати або змінити правило

1. Змінити або додати файл у `critical/`. Як писати правила: `docscan-project/CRITICAL-RULES.md` у репозиторії
   програми.
2. Додати документи-приклади в `tests/match/` (має знайти) і `tests/no-match/` (не має знайти).
3. `git commit`.
4. Перевірка без публікації (з репозиторію програми):
   ```
   go run -C docscan-project/ci/cirun . rules-release --dir ~/yara-docscan-rules --critical ~/docscan-critical --dry-run
   ```
   Інструмент перевіряє основні правила, імена файлів і компіляцію критичних правил і проганяє всі документи
   `tests/`. Що не знайдено — `NOT FOUND`, що спрацювало зайве — `FALSE ALARM`. Будь-яка помилка означає, що
   пакета немає.
5. Зелено → `git push` цього репозиторію; реліз — та сама команда без `--dry-run`. Реліз робиться на коміт
   репозиторію правил: якщо змінилися лише критичні правила, спершу закомітьте й запуште щось у
   `yara-docscan-rules`.

ПК отримують новий пакет через службу DocScanUpdater, як і основні правила.
